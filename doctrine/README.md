# Doctrine (v0.3)

Two kinds of text live here.

**Operating doctrine** is what a later reader has to obey.

1. [CONSTITUTION.md](CONSTITUTION.md) — the test (evaluation revision of v0.2; not permanently frozen)
2. [MODEL.md](MODEL.md) — lifecycle and the four objects

**Audit record** is how that doctrine was tested. It may grow. It is not a second set of rules. If a trial changes what must be obeyed, the change is written into the Constitution or the model.

3. [PROJECT-ZERO.md](PROJECT-ZERO.md) — this system, entered as a draft
4. [TRIALS.md](TRIALS.md) — confirmatory pass, then trials meant to invalidate the doctrine
5. [trials/](trials/) — fixtures and the results of running them
6. [trials/F6-cedar-trail-f6c.md](trials/F6-cedar-trail-f6c.md) — a later reading under a candidate inference rule. Not installed.
7. [trials/DEPENDABLE-INFERENCE-EVALUATION.md](trials/DEPENDABLE-INFERENCE-EVALUATION.md) — the score. More trials are required. The rule is not adopted.

Read the operating doctrine first. Do not start from architecture.

Nothing here is software. Commit is a user action. Reversible does not mean authorized. The public description is unchanged until the intent question is deliberately resolved.
